# 큰길브리지 전자명함 서버 (Google Apps Script)

`card/index.html` 의 **「명함 발행하기」** 가 쓰는 백엔드입니다.
손님은 **신청 · 접수 문자 · 비밀번호 없이** 바로 만들어 발행합니다. 서버가 받은 자료로 명함을 직접 그려 저장소 **main 브랜치**에 쓰면, 깃허브 페이지가 1~2분 안에 올려 줍니다.

```
card/{주소}/index.html   완성된 명함 (og 태그가 박혀 카톡 미리보기가 뜬다)
card/img/{주소}.jpg      인물 사진 (작은 동그라미)
card/bg/{주소}.jpg       배경 사진 (크게 깔린다)
card/og/{주소}.jpg       카톡·문자 미리보기용 1200×630
```

## ⚠ 지금 고칠 것 (2026-09-21 확인)

명함 서버 주소(`…/AKfycbxSIKrM5…/exec`)를 열면 **「큰길브리지 문의폼 수신 서버 정상」** 이 나옵니다.
9월 15일에 **문의 서버 코드가 명함 서버 프로젝트에 붙여넣어진 것**입니다. 그래서 그날 뒤로 명함이 하나도 발행되지 않았습니다.
아래 순서로 **명함 코드(이 폴더의 `Code.gs`)를 다시 붙여넣으면** 끝납니다. 주소는 그대로입니다.

1. https://script.google.com → 프로젝트 목록에서 **명함 프로젝트**를 엽니다.
   어느 것인지 헷갈리면: 프로젝트를 열고 **배포 → 배포 관리** 에 나오는 웹 앱 주소가 `AKfycbxSIKrM5` 로 시작하는 것이 명함 프로젝트입니다.
   (`AKfycbwvQ4UJ` 로 시작하면 문의 서버입니다. 그건 건드리지 마세요.)
2. `Code.gs` 내용을 **전부 지우고**, 이 폴더의 **`Code.gs`** 를 통째로 붙여넣기 → 저장
   - 복사하기 편한 주소 → https://github.com/brizymedia/ai-make/blob/main/apps-script/card/Code.gs (오른쪽 위 복사 단추)
   - 붙여넣은 뒤 맨 위 줄이 `큰길브리지 — 전자명함 서버` 인지 확인
3. 위쪽 함수 고르는 칸에서 **`점검`** → **실행**. 권한 창이 뜨면 계정 선택 → 고급 → 이동 → 허용.
   아래 로그에 이 두 줄이 보이면 됩니다.
   ```
   쓰기 권한 정상 — 이 토큰으로 명함을 올릴 수 있습니다
   명함 틀 정상 — 사이트의 template.js 로 그렸습니다
   ```
4. **배포 → 배포 관리 → 연필 → 버전: 새 버전 → 배포** (「새 배포」가 아닙니다 — 주소가 바뀝니다)
5. 확인: 명함 서버 주소를 브라우저로 열어 이렇게 나오면 성공입니다.
   ```
   {"ok":true,"service":"keungil-card","version":"2026-09-21a","render":"server","open":true}
   ```
   그러면 www.ai-make.co.kr/card 의 「명함 서버 점검 중」 안내가 저절로 사라지고 발행이 열립니다.

## 어떻게 지키나 (비밀번호 없이 열어 두는 대신)

| 지키는 것 | 방법 |
|---|---|
| 우리 도메인에 남의 페이지가 올라가지 않게 | 서버는 **HTML 을 받지 않습니다.** 이름 · 전화 같은 자료만 받아, 사이트의 명함 틀(`card/template.js`, 만들기 화면의 미리보기와 같은 파일)로 **서버가 직접 그립니다.** 글자는 모두 이스케이프됩니다 |
| 남이 내 명함을 덮어쓰지 못하게 | 발행할 때 그 브라우저가 만든 **기기 열쇠**의 지문(SHA-256)을 명함 안에 박아 둡니다. 같은 주소에 다시 올리려면 열쇠가 맞아야 합니다. 열쇠가 없는 옛 명함(brizy 등)이나 다른 기기에서 고칠 때는 **관리자 비밀번호**로만 |
| 도배 | 하루 발행 수 제한(기본 80장), 같은 전화번호 6시간에 8번. 사진은 JPG · 900KB 이하만 |
| 급할 때 | 스크립트 속성 `OPEN_PUBLISH` = `off` → 관리자만 발행 (배포를 다시 하지 않아도 바로 적용) |

## 스크립트 속성 (⚙ 프로젝트 설정 → 맨 아래)

| 속성 | 값 |
|---|---|
| `GITHUB_TOKEN` | **필수.** `github_pat_…` — brizymedia/ai-make 에 Contents: Read and write |
| `GITHUB_REPO` | **필수.** `brizymedia/ai-make` |
| `UPLOAD_PW` | 선택. **관리자 비밀번호** — 남의 명함 · 옛 명함 고치기, 명함 지우기에 씁니다. 예전에 넣어 둔 값이 그대로 관리자 비밀번호가 됩니다. 없으면 그 기능이 꺼집니다 |
| `OPEN_PUBLISH` | 선택. `off` 면 관리자만 발행 |
| `OPEN_DAILY_MAX` | 선택. 하루 발행 수. 비우면 80 |

> 토큰 · 비밀번호는 저장소 열쇠와 같습니다. 카톡 · 메일로 보내지 마시고, 이 문서나 코드 파일에도 적지 마세요. 스크립트 속성에만 둡니다.

## 관리자로 쓰기

- www.ai-make.co.kr/card/**?admin=1** 로 열면 발행 칸에 「관리자 비밀번호」 칸이 보입니다. `UPLOAD_PW` 값을 넣으면 어떤 명함이든 고칠 수 있습니다(주인의 기기 열쇠는 그대로 남습니다).
- 명함 지우기: 저장소에서 `card/{주소}/` 폴더와 `card/img|bg|og/{주소}.jpg` 를 지우거나, 클대리에게 「○○ 명함 지워줘」.

## 명함이 발행되면 남는 것

1. 저장소 main 에 위 네 파일 (명함 자체)
2. 구글 드라이브 **「이벤트 코리아 / 이벤트인 명단」** 시트에 한 줄 — 이름 · 전화 · 직군 · 출처(명함) · 문자동의 · 메모(상호 · 이메일 · 명함 주소). 같은 번호면 그 줄을 갱신
3. 형님 메일로 **「[큰길브리지 문의] ○○ / 상호 님 — 전자명함 발행」** 알림 한 통 (만들기 화면이 문의 서버로 보냄. 고쳐서 다시 발행할 때는 안 보냄)

## 토큰을 새로 만들어야 할 때

1. 깃허브 오른쪽 위 프로필이 **brizymedia** 인지 확인 (다른 계정으로 만든 토큰은 403)
2. https://github.com/settings/personal-access-tokens/new
   - Token name `큰길 명함 발행` · Expiration `No expiration`
   - Repository access → **Only select repositories** → `brizymedia/ai-make`
   - Permissions → Repository permissions → **Contents → Read and write**
3. Generate token → `github_pat_…` 복사 → 스크립트 속성 `GITHUB_TOKEN` 에 (배포를 다시 할 필요 없음)

## 문제가 생기면

| 증상 | 원인과 해결 |
|---|---|
| 만들기 화면에 「명함 서버를 점검하고 있습니다」 | 서버 주소에서 명함 코드가 안 돌고 있음 → 맨 위 「지금 고칠 것」 |
| 「깃허브 저장 실패 (403) Resource not accessible by personal access token」 | 토큰에 이 저장소 쓰기 권한이 없음 → 위 「토큰을 새로 만들어야 할 때」. `점검` 이 「쓰기 권한 정상」이라고 해야 함 |
| 「깃허브 저장 실패 (404)」 | `GITHUB_REPO` 오타 — `brizymedia/ai-make` |
| 「명함 틀을 읽지 못했습니다」 | 사이트의 `card/template.js` 를 못 읽음. 잠시 뒤 다시. 계속되면 클대리에게 |
| 「이미 쓰고 있는 주소입니다」 | 다른 사람이 쓰는 주소이거나, 내 명함인데 다른 기기에서 고치려는 것 → 처음 만든 기기에서 고치거나 새 주소로 |
| 「오늘은 발행이 많아 잠시 닫았습니다」 | 하루 한도 → `OPEN_DAILY_MAX` 를 올리거나 내일 |
| 코드를 고쳤는데 그대로 | 앱스 스크립트는 저장만으로 안 바뀜 → **배포 관리 → 연필 → 새 버전 → 배포** |
