# 큰길브리지 갤러리 글 발행 서버 설치 (Google Apps Script)

`gallery/write.html` 의 **「홈페이지에 올리기」** 버튼이 쓰는 무료 백엔드입니다.

| | 서버 없을 때 | 서버 설치 후 |
|---|---|---|
| 글 올리기 | HTML 내려받기 → 저장소에 직접 올리기 | **버튼 하나** |
| 목록 · 사이트맵 · RSS | `node build-sitemap.js` 실행 후 커밋 | **자동** (1~2분) |
| 올리는 곳 | 컴퓨터 앞에서만 | **휴대폰에서도** |

> **서버 없이도 글은 올라갑니다.** 설치는 편의용입니다.
> 서버가 죽어도 「HTML 파일 내려받기」로 올리면 결과는 똑같습니다.

---

## 1) GitHub 토큰 만들기 (3분)

글을 저장소에 올리려면 쓰기 권한이 있는 토큰이 필요합니다.

1. https://github.com/settings/personal-access-tokens/new 열기
2. 입력
   - **Token name**: `큰길브리지 글 발행`
   - **Expiration**: `No expiration` (또는 1년 — 만료되면 다시 만들어야 합니다)
   - **Repository access**: `Only select repositories` → **`brizymedia/ai-make`** 선택
3. **Permissions → Repository permissions** 에서 **`Contents`** 를 **`Read and write`** 로 바꿉니다
   (글 저장과 목록 갱신 신호에 둘 다 이 권한을 씁니다. 다른 항목은 건드리지 마세요)
4. **Generate token** → 나오는 `github_pat_…` 문자열을 복사해 둡니다
   **이 화면을 벗어나면 다시 볼 수 없습니다.** 잃어버리면 새로 만들면 됩니다.

> 토큰은 저장소 비밀번호와 같습니다. 카톡·메일로 보내지 마시고, 이 문서나 코드 파일에도 적지 마세요.
> 아래 2단계의 「스크립트 속성」에만 넣습니다.

## 2) 스크립트 만들기 (5분)

1. **https://script.new** 접속 (새 프로젝트가 열립니다)
2. 기본으로 열린 `Code.gs` 내용을 **전부 지우고** 이 폴더의 **`큰길브리지-갤러리서버.gs`** 를 통째로 붙여넣습니다
3. 프로젝트 이름을 **`큰길브리지 글 발행`** 으로 바꾸고 저장
4. 왼쪽 **⚙ 프로젝트 설정** → 맨 아래 **스크립트 속성** → **스크립트 속성 추가** 로 세 개를 넣습니다

   | 속성 | 값 |
   |---|---|
   | `WRITE_PW` | 글 올릴 때 칠 비밀번호 (직접 정하세요) |
   | `GITHUB_TOKEN` | 1단계에서 복사한 `github_pat_…` |
   | `GITHUB_REPO` | `brizymedia/ai-make` |

5. **저장**

## 3) 배포하기

**배포 → 새 배포 → 유형: 웹 앱**

| 항목 | 값 |
|---|---|
| 실행 사용자 | **나** |
| 액세스 권한 | **모든 사용자** |

> ⚠️ **"Google 계정이 있는 모든 사용자"는 안 됩니다.**
> 이름만 보면 될 것 같지만, 브라우저가 로그인 창을 만나 요청이 막힙니다.
> 반드시 **`모든 사용자`** 여야 합니다.

권한 승인 창이 뜹니다. 바깥 인터넷(깃허브)에 연결하기 때문입니다.
"안전하지 않다"는 경고가 나오면 **고급 → 이동** 을 누르면 됩니다.

승인 창이 안 뜨고 나중에 `UrlFetchApp.fetch를 호출할 수 있는 권한이 없습니다` 가 나오면,
편집기 위쪽 함수 목록에서 **`권한받기`** 를 골라 **실행** 한 뒤 배포를 새 버전으로 다시 하세요.

배포를 누르면 나오는 **웹 앱 URL** 을 복사합니다.

```
https://script.google.com/macros/s/AKfyc.../exec
```

## 4) 글쓰기 도구에 연결

`gallery/write.html` 을 열고 → 결과 칸 아래 **「홈페이지에 바로 올리기」** 에

- **발행 서버 주소** — 위에서 복사한 URL
- **발행 비밀번호** — `WRITE_PW` 에 넣은 값

을 넣고 **「이 기기에 주소 · 비밀번호 기억」** 을 켜두면 다음부터 안 넣어도 됩니다.

## 5) 잘 되는지 확인

웹 앱 URL 을 브라우저 주소창에 그냥 넣어보세요. 이렇게 나오면 정상입니다.

```json
{"ok":true,"service":"keungil-bridge-gallery","version":1,
 "설정완료":{"WRITE_PW":true,"GITHUB_TOKEN":true,"GITHUB_REPO":true}}
```

`설정완료` 에 `false` 가 있으면 2단계의 스크립트 속성을 다시 보세요.

편집기에서 **`점검`** 함수를 실행하면 로그에 더 자세히 나옵니다.

## 올리면 벌어지는 일

```
write.html 「홈페이지에 올리기」
   ↓
앱스 스크립트가 gallery/posts/글.html 을 저장소에 커밋
   ↓
GitHub Actions 가 깨어남 (.github/workflows/gallery.yml)
   ↓
node build-sitemap.js 실행
   ↓
gallery/index.html 목록 · sitemap.xml · rss.xml 다시 만들어 커밋
   ↓
1~2분 뒤 홈페이지에 보임
```

**목록을 손으로 고칠 일이 없습니다.** `gallery/posts/` 의 글 파일이 곧 목록입니다.
글 파일을 지우면 목록 · 사이트맵 · RSS 에서도 저절로 빠집니다.

신호가 실패해도 **매일 아침 6시 23분**에 도는 자동 작업이 어차피 갱신합니다.

## 주의할 것

**같은 파일명은 덮어쓰지 않습니다.** 실수로 두 번 눌러 글이 사라지는 일을 막기 위해서입니다.
같은 파일명이 이미 있다고 나오면 제목이나 날짜를 바꿔 파일명을 다르게 만드세요.

**파일명에 폴더를 넣을 수 없습니다.** `/` 나 `..` 가 들어가면 거부합니다.
브라우저에서 오는 값이라 그대로 믿으면 저장소의 엉뚱한 파일을 덮어쓸 수 있기 때문입니다.

**비밀번호는 이 기기에만 저장됩니다.** 공용 컴퓨터에서는 「기억」을 꺼두세요.

**코드를 고친 뒤에는** — 배포 → 배포 관리 → 연필 아이콘 → 버전: 새 버전 → 배포

- 연필로 수정 → **주소 그대로 유지** ✅
- 새 배포 → **주소가 새로 발급됨** ❌ (글쓰기 도구에 넣은 주소를 다시 바꿔야 함)

## 사장님 직접 편집 붙이기 (2026-09 추가)

같은 서버가 **사장님이 글자·사진을 직접 고치는 요청**도 받습니다. 따로 만들 것 없습니다.

1. 이 폴더의 `큰길브리지-갤러리서버.gs` 를 다시 통째로 복사해 편집기에 붙여넣습니다 (기존 내용 지우고)
2. **배포 → 배포 관리 → 연필(✏️) → 버전: 새 버전 → 배포**  ← 「새 배포」 아니고 연필입니다
3. 주소는 그대로입니다. 그 `/exec` 주소를 `edit.js` 맨 위 `var 서버 = ''` 에 넣습니다 (저에게 주시면 제가 넣습니다)

비밀번호는 안 씁니다. 페이지마다 **열쇠**가 다릅니다.

- 페이지 `<head>` 에 `<meta name="kb-edit" content="열쇠의 SHA-256">` 이 있으면 그 페이지는 편집이 열린 겁니다
- 열쇠 만들기: `node -e "console.log(require('crypto').createHash('sha256').update('열쇠','utf8').digest('hex'))"`
- 사장님께 보내는 문자: **「사이트주소/?edit=열쇠 로 들어가시면 글자를 눌러 고칠 수 있어요. 고치고 「저장」 누르시면 1~2분 뒤 반영돼요.」**
- 열쇠를 바꾸려면 메타의 해시만 바꿔 올리면 됩니다. 옛 열쇠는 그 순간 죽습니다

서버 주소가 비어 있으면 `edit.js` 는 **시안 모드**로 돕니다 — 그 기기에만 저장되고 화면엔 똑같이 고쳐진 것으로 보입니다. 시연할 때 그대로 쓰면 됩니다.
