404 페이지 만들기 — soft 404 피하고 홈 · 인기 메뉴 · 연락 버튼 넣는 법

2026-10-30 · 큰길브리지 · 읽는 시간 약 5분
404 페이지soft 404맞춤 404HTTP 상태 코드

404 페이지는 '없는 주소'를 정직하게 알리되, 손님이 다음에 누를 곳을 함께 보여 주는 화면이어야 합니다. 핵심은 두 가지입니다. 서버는 반드시 404 상태 코드를 돌려주고, 화면에는 홈 · 인기 메뉴 · 연락 경로를 둡니다. 화면만 예쁘게 꾸미고 상태 코드를 200(정상)으로 돌려주면 Google이 soft 404로 분류합니다. 주소를 옮긴 페이지라면 404가 아니라 301 이동이 맞고, 그 방법은 리뉴얼 주소 변경 글에 따로 정리했습니다.

핵심만 먼저
  • Search Console 도움말은 404 오류 자체가 검색 성과에 영향을 주지 않으며, 많은 404는 고칠 필요가 없다고 안내합니다.
  • soft 404는 '페이지가 없다'고 보여 주면서 200(성공) 코드를 돌려주는 주소입니다. 없는 주소를 전부 홈으로 보내는 것도 여기에 해당합니다.
  • Google은 맞춤 404 페이지에 사이트와 같은 디자인 · 메뉴, 홈과 인기 글 링크, 깨진 링크 신고 경로를 넣으라고 권합니다.
  • 만든 뒤에는 아무 주소나 열어 보고, URL 검사 도구로 실제 돌려주는 코드가 404인지 확인합니다.

1404가 뜨면 검색 순위가 떨어지나요?

대부분은 아닙니다. Search Console 도움말은 404 오류가 사이트의 색인이나 순위에 영향을 주지 않으며, 원래 없던 주소에서 생긴 404는 대개 걱정할 필요가 없다고 설명합니다. 다만 사이트맵으로 직접 제출한 주소가 404라면 고쳐야 합니다. Google의 HTTP 상태 코드 문서에 따르면 404 같은 4xx 코드를 돌려주는 주소는 색인을 만들지 않고, 이미 색인된 주소도 시간이 지나며 빠집니다.

페이지 상황돌려줄 코드근거
지웠고 비슷한 대체 페이지가 없음404 또는 410Google은 현재 410을 404와 똑같이 취급(Search Console 도움말)
다른 주소로 옮겼거나 확실한 대체 페이지가 있음301검색엔진에 새 위치를 알림(크롤링 오류 문서)
손님이 자주 틀리게 치는 주소리디렉션예: cancelling · canceling 처럼 철자가 갈리는 주소(Search Console 도움말)
원래 없던 엉뚱한 주소404 그대로대부분 해결할 필요 없음, 약 한 달 뒤 보고서에서 사라짐

2soft 404는 무엇이고, 왜 생기나요?

soft 404는 화면에는 '페이지가 없습니다'라고 쓰여 있는데 서버는 200(성공) 코드를 돌려주는 주소입니다. 손님은 정상 페이지인 줄 알고 들어왔다가 오류 문구를 만나고, Google은 내용을 보고 오류 페이지로 판단해 페이지 색인 생성 보고서에 soft 404로 표시합니다. Google 크롤링 오류 문서가 드는 원인은 이렇습니다.

  • 서버 쪽 포함 파일이 빠졌거나 데이터베이스 연결이 끊긴 경우
  • 가게 안 검색 결과 페이지가 텅 빈 경우
  • 자바스크립트 파일이 없거나 불러오다 멈춘 경우
  • 없는 주소를 모두 홈 화면으로 돌려보내는 경우(Search Console 도움말은 이것을 하지 말라고 안내합니다)
멀쩡한 페이지가 soft 404로 잡혔다면 Googlebot이 이미지 · 스크립트를 제대로 불러오지 못했을 수 있습니다. URL 검사 도구로 렌더링된 화면과 돌려준 코드를 함께 봅니다.

3맞춤 404 페이지 화면에는 무엇을 넣나요?

Google 크롤링 오류 문서는 유용한 맞춤 404 페이지를 위해 다섯 가지를 권합니다.

  1. 찾는 페이지가 없다는 사실을 분명하게, 친근한 말로 알립니다.
  2. 디자인과 상단 메뉴를 사이트의 다른 페이지와 똑같이 둡니다.
  3. 홈 링크와 함께 가장 많이 보는 글 · 메뉴 링크를 넣습니다.
  4. 깨진 링크를 알려 줄 수 있는 경로를 둡니다.
  5. 화면은 손님용이지만, 서버는 반드시 404 상태 코드를 돌려주게 합니다.

아래는 공식 기준이 아니라 가게 홈페이지에서 흔히 쓰는 일반 요령입니다. 식당이라면 '메뉴 · 오시는 길 · 예약', 학원이라면 '시간표 · 상담 신청'처럼 가장 많이 찾는 버튼 세 개만 큼직하게 둡니다. 휴대폰에서 누르는 전화 버튼, 사이트 안 검색창이 있다면 검색창도 함께 둡니다. '주소가 잘못되었습니다'처럼 손님 탓으로 들리는 문장은 피합니다.

4만든 뒤에는 어떻게 확인하나요?

  1. 주소 뒤에 아무 글자나 붙여(예: /abc123) 열어 보고 맞춤 화면이 뜨는지 봅니다.
  2. Search Console URL 검사 도구에 그 주소를 넣어 실제로 404를 돌려주는지 확인합니다. Google 문서도 이 도구로 코드를 확인하라고 안내합니다.
  3. 페이지 색인 생성 보고서에서 soft 404 항목이 있는지 봅니다.
  4. 404 목록 중 사이트맵에 넣은 주소가 있으면 사이트맵을 고치거나 301로 옮깁니다. 목록을 나누는 법은 연말 점검 글에 있습니다.
robots.txt로 404 주소를 막거나 가짜 내용을 채우는 것도 Search Console 도움말이 하지 말라고 한 방법입니다. 없는 페이지는 없다고 알리는 것이 가장 깔끔합니다.

5GitHub Pages나 빌더로 만든 홈페이지는 어디서 설정하나요?

GitHub Pages는 공식 문서에 방법이 있습니다. 사이트 저장소의 게시 위치에 404.html 또는 404.md 파일을 새로 만들고, 404.md라면 맨 위에 permalink: /404.html 머리말을 넣은 뒤 내용을 적어 커밋하면 없는 주소에서 그 화면이 나옵니다. 홈페이지 빌더는 서비스마다 메뉴가 달라 관리 화면에서 '404' 또는 '오류 페이지' 설정이 있는지 직접 확인해야 합니다. 호스팅 방식별 차이는 웹호스팅 고르기 글에 정리했습니다.

우리 홈페이지에서 404 · soft 404가 얼마나 나오는지 모르겠다면 무료 SEO 점검으로 먼저 확인해 보셔도 됩니다.

자주 묻는 질문

없는 주소를 전부 홈으로 보내면 손님이 덜 헤매지 않나요?

Google Search Console 도움말은 없는 페이지를 홈으로 리디렉션하지 말라고 안내합니다. soft 404로 처리되어 사용자와 검색엔진 모두 혼란스러워질 수 있습니다. 옮긴 페이지만 가장 비슷한 새 주소로 301 이동하고, 나머지는 404를 돌려주면서 화면에 홈 링크를 둡니다.

Search Console에 404가 많이 쌓였는데 다 고쳐야 하나요?

아닙니다. 도움말은 많은, 어쩌면 대부분의 404는 고칠 필요가 없다고 설명합니다. 사이트맵으로 제출한 주소, 다른 곳으로 옮긴 페이지, 손님이 자주 틀리게 치는 주소만 골라 처리합니다.

404와 410 중 무엇을 써야 하나요?

Search Console 도움말 기준으로 Google은 현재 410을 404와 똑같이 취급합니다. 홈페이지 프로그램에서 쉽게 설정되는 쪽을 쓰면 됩니다.
