화성 영문 홈페이지 — 영어 페이지 주소 나누기 · hreflang · 언어 전환 링크

2026-10-14 · 큰길브리지 · 읽는 시간 약 7분
화성 영문 홈페이지영어 페이지 만들기hreflang 설정다국어 홈페이지

화성 영문 홈페이지를 만들 때 첫 결정은 번역 문장이 아니라 주소입니다. Google 검색 센터는 쿠키나 브라우저 설정으로 같은 주소의 언어를 바꾸지 말고 언어마다 다른 URL을 쓰라고 권장합니다. 그다음 hreflang으로 '이 페이지의 영어판은 저기'라고 서로 알려 주고, 손님이 직접 고르는 언어 전환 링크를 둡니다. 접속 위치(IP)를 보고 자동으로 보내는 방식은 Google이 하지 말라고 적은 방법입니다.

핵심만 먼저
  • 언어마다 주소를 따로 둡니다(예: /en/). Google 크롤러는 언어 설정 헤더를 보내지 않아, 한 주소에서 언어만 바꾸면 영어판이 검색에 잡히지 않을 수 있습니다.
  • hreflang은 각 페이지가 자기 자신과 다른 언어판을 모두 적고, 서로 가리켜야 합니다. 한쪽만 적으면 무시됩니다.
  • 언어를 추측해 자동으로 이동시키거나 IP로 내용을 바꾸지 말고, 화면에 언어 전환 링크를 둡니다.
  • 번역본에는 '한국어 안내가 기준'이라는 한 줄과 가격 · 시간 · 주소의 원문 대조가 필요합니다(일반적인 권장).

1영어 페이지는 왜 주소를 따로 둬야 하나요?

Google 검색 센터의 '다지역 및 다국어 사이트 관리' 문서는 쿠키나 브라우저 설정으로 콘텐츠 언어를 바꾸는 방법보다 페이지 URL을 언어별로 달리 하라고 권장합니다. 이유도 적혀 있습니다. Google 크롤러는 주로 미국에서 접속하고 언어 설정 헤더(Accept-Language)를 보내지 않기 때문에, 설정에 따라 글이 바뀌는 페이지는 모든 언어판이 수집되지 않을 수 있습니다.

언어 판단 기준도 알아 둘 만합니다. Google은 lang 속성이나 주소가 아니라 페이지에 보이는 글로 언어를 정합니다. 한 페이지에 한국어와 영어를 위아래로 나란히 넣기보다, 한국어 페이지와 영어 페이지를 각각 한 언어로 만드는 편이 문서 권장에 맞습니다. 메뉴 · 버튼 같은 고정 글자까지 그 언어로 바꿉니다.

2영어판 주소 구조는 무엇으로 고르나요?

Google 문서가 비교한 네 가지 구조를 작은 가게 기준으로 옮기면 아래와 같습니다. 장단점은 문서 내용이고, 마지막 칸은 큰길브리지가 덧붙인 판단입니다.

구조예시문서상 장점문서상 단점작은 가게 판단
국가 도메인(ccTLD)example.us지역 타겟이 분명비용 · 관리 부담, 한 나라만 대상보통 필요 없음
하위 도메인en.example.com설정이 쉬움주소만 보고 언어를 알기 어려울 수 있음호스팅이 따로일 때
하위 디렉터리example.com/en/설정이 쉽고 유지 비용이 낮음서버 위치가 하나가장 무난
URL 매개변수example.com?lang=en-Google이 권장하지 않음피함
주소를 정했으면 한국어 페이지 하나에 영어 페이지 하나가 짝을 이루게 만듭니다. 한국어 메뉴 페이지의 짝은 영어 메뉴 페이지, 오시는 길의 짝은 영어 오시는 길입니다. 짝이 분명해야 다음 단계의 hreflang을 적을 수 있습니다.

3hreflang은 어떤 순서로 적나요?

hreflang은 '이 페이지의 다른 언어판은 이 주소'라고 검색엔진에 알리는 표시입니다. Google은 HTML 머리말(head)의 link 태그, HTTP 헤더, 사이트맵 세 방법을 지원하고 셋은 같은 효과라고 설명합니다. 일반 홈페이지라면 link 태그가 가장 손쉽습니다.

  1. 짝 목록 만들기 — 한국어 주소와 영어 주소를 표로 적습니다.
  2. 언어 코드 고르기 — 한국어는 ko, 영어는 en입니다. 지역을 붙일 때는 en-US처럼 언어 코드 뒤에 붙이고, 지역 코드만 단독으로 쓰지 않습니다.
  3. 양쪽 페이지에 모두 적기 — 한국어 페이지에도, 영어 페이지에도 ko와 en 두 줄을 똑같이 넣습니다. 자기 자신도 목록에 넣는 것이 규칙입니다.
  4. 전체 주소로 적기 — https:// 부터 시작하는 전체 주소를 씁니다.
  5. x-default 정하기(선택) — 언어 선택 화면이 따로 있으면 그 주소를 x-default로 둡니다. 어느 언어에도 맞지 않는 사용자에게 보여 줄 페이지라는 뜻입니다.
  6. 확인하기 — Search Console의 URL 검사로 두 페이지가 모두 수집되는지 봅니다. 사용법은 인천 구글 서치콘솔 글에 있습니다.
가장 흔한 실수는 돌아오는 링크 누락입니다. Google 문서는 두 페이지가 서로를 가리키지 않으면 태그가 무시된다고 적고 있습니다. 영어 페이지만 고치고 한국어 페이지를 빠뜨리지 않았는지 꼭 확인합니다.

4외국 손님은 영어 페이지로 자동으로 보내면 안 되나요?

편해 보이지만 Google 문서는 반대합니다. 사용자의 언어를 추측해 리디렉션하지 말 것, IP 분석을 바탕으로 콘텐츠를 조정하지 말 것을 따로 적어 두었습니다. 자동 이동은 손님과 검색엔진 모두가 다른 언어판을 보지 못하게 만들고, IP 위치 추정은 부정확할 수 있다는 이유입니다.

  • 화면 위쪽(헤더)에 'English' / '한국어' 전환 링크를 둡니다. 국기 그림보다 언어 이름 글자가 알아보기 쉽습니다.
  • 전환 링크는 영어 첫 화면이 아니라 지금 보고 있는 페이지의 짝으로 연결합니다.
  • 한국에 사는 외국인이 한국어판을, 해외의 교민이 한국어판을 볼 수도 있습니다. 고르는 사람은 손님입니다.

5번역은 번역기로 돌려도 되나요?

Google 스팸 정책의 '확장된 콘텐츠 악용' 항목은 다른 콘텐츠를 긁어 와 번역 같은 자동 변환으로 가치 낮은 페이지를 대량으로 만드는 것을 예로 듭니다. 내 가게 소개를 번역기로 초안 잡는 일 자체를 다룬 문장은 아니지만, 검토 없이 쌓은 번역 페이지가 좋은 평가를 받기 어렵다는 방향은 분명합니다.

아래는 공식 기준이 아닌 일반적인 점검 요령입니다. 기계 번역을 초안으로 쓰더라도 사람이 한 번은 읽고 고칩니다.

  • 가격 · 영업시간 · 휴무일 · 전화번호 같은 숫자는 한국어 원문과 한 줄씩 대조합니다.
  • 메뉴 이름은 소리 나는 대로 적고 짧은 설명을 붙입니다(예: Tteokbokki — spicy rice cakes).
  • 예약 · 환불 · 알레르기처럼 오해가 손해로 이어지는 문장은 원어민이나 해당 언어에 익숙한 사람에게 확인을 받습니다.
  • 번역본 맨 아래에 '내용이 다를 경우 한국어 안내가 기준입니다(The Korean version prevails)' 같은 한 줄을 둡니다.

처음부터 모든 페이지를 옮길 필요는 없습니다. 외국인 손님이 실제로 찾는 첫 화면 · 메뉴(서비스) · 오시는 길 · 예약 문의 네 곳부터 시작하면 관리할 분량이 줄어듭니다.

6화성 가게라면 영어 안내에서 무엇을 함께 맞추나요?

4개 구청만세 · 효행 · 병점 · 동탄구청(화성특례시청 누리집)

화성특례시청 누리집의 '민원서식 외국어 해석본'은 출생 · 혼인 · 이혼 신고서와 증명서 교부 신청서 등 4종 양식을 영어 · 중국어 · 베트남어 등 10개국어로 옮겨 두었습니다. 그러면서 번역문은 작성을 돕는 참고용이고 신고는 한글 양식에 해야 한다고 유의사항을 붙였습니다. 가게 영어 페이지에 '한국어 안내가 기준'이라는 문장을 두는 것과 같은 생각입니다.

주소도 다시 볼 때입니다. 시청 누리집 하단에는 만세 · 효행 · 병점 · 동탄 4개 구청 누리집이 따로 연결되어 있고, 시청 주소는 '경기도 화성시 만세구 남양읍 시청로 159'로 적혀 있습니다. 한국어 페이지의 주소, 영어 페이지의 주소, 지도 앱 정보가 같은 구 이름을 쓰는지 대조합니다. 주소를 검색엔진 형식으로 함께 적는 법은 용인 구조화 데이터 글에 정리했습니다.

큰길브리지는 영어 페이지 추가와 언어 전환 링크 · hreflang 설정을 전국 비대면으로 진행합니다. 지금 홈페이지 주소를 제작 문의에 남겨 주시면 어떤 페이지부터 옮길지 함께 정합니다.

자주 묻는 질문

영어 페이지를 만들면 해외 검색에 바로 나오나요?

보장되지 않습니다. 언어별 주소와 hreflang은 Google이 언어판을 찾고 맞는 사용자에게 연결하도록 돕는 장치입니다. 노출 여부는 콘텐츠와 검색어에 따라 달라집니다.

hreflang을 한국어 페이지에만 넣어도 되나요?

안 됩니다. Google 문서는 각 언어판이 자기 자신과 다른 언어판을 모두 나열해야 하고, 두 페이지가 서로를 가리키지 않으면 태그가 무시된다고 설명합니다.

브라우저 언어가 영어면 자동으로 영어 페이지를 보여 줘도 되나요?

Google은 사용자의 언어를 추측해 리디렉션하지 말고, 다른 언어판으로 가는 링크를 두어 사용자가 고르게 하라고 권장합니다.

번역기 결과를 그대로 올리면 문제가 되나요?

검토 없이 올린 번역은 가격 · 시간 오류와 어색한 표현이 남기 쉽습니다. Google 스팸 정책도 자동 번역으로 가치 낮은 페이지를 대량으로 만드는 것을 문제 사례로 듭니다. 초안으로 쓰고 사람이 숫자와 핵심 문장을 대조하는 것을 권합니다.
