웹호스팅정적 호스팅홈페이지 빌더호스팅 이전

웹호스팅은 값이나 속도보다 '그만둘 때 내 홈페이지를 들고 나올 수 있는가'로 먼저 고르는 편이 안전합니다. 같은 홈페이지라도 정적 호스팅, 일반 웹호스팅, 홈페이지 빌더 중 어디에 올리느냐에 따라 백업을 누가 하는지, 인증서(SSL)를 누가 붙이는지, 주소를 옮길 수 있는지가 달라집니다. 계약 전에 네 가지만 물어보면 대부분 가려집니다.

핵심만 먼저
  • 정적 호스팅은 완성된 파일만 올리고, 일반 웹호스팅은 서버 프로그램까지 돌리며, 빌더는 편집 화면과 서버가 한 몸입니다.
  • 계약 전 질문은 네 가지 — 백업은 누가, SSL은 자동인가, 도메인은 누구 명의인가, 파일을 들고 나올 수 있는가.
  • GitHub Pages는 사이트 1GB 이하 · 월 100GB 소프트 대역폭 한도가 있고, 온라인 비즈니스 · 전자상거래 용도로는 허용되지 않습니다.
  • Google Sites 맞춤 주소는 확인된 도메인에만 연결되고 인증서는 자동 발급되며, 다른 인증서는 쓸 수 없습니다.
  • 서버를 직접 운영한다면 KISA 보호나라의 '내 서버 돌보미'로 원격 보안 점검을 신청할 수 있습니다(중소기업 대상).

1세 가지 방식은 무엇이 다른가요?

호스팅은 홈페이지 파일을 올려 두는 서버이고, 도메인은 그 서버로 가는 주소입니다. 이 둘의 연결은 도메인 연결 글에서 다뤘으니, 여기서는 '어떤 서버에 올릴까'만 봅니다.

방식올라가는 것사장님이 챙길 일옮길 때
정적 호스팅완성된 HTML · 이미지 파일파일 원본 보관파일을 그대로 다른 곳에 올리면 됨
일반 웹호스팅파일 + 서버 프로그램(게시판 · DB 등)프로그램 업데이트 · 백업 · 보안파일과 DB를 함께 옮겨야 함
홈페이지 빌더빌더 회사 화면 안에서 만든 페이지계정 · 결제 유지빌더마다 내보내기 범위가 다름

문의 폼 몇 개와 소개 페이지뿐인 가게라면 정적 호스팅이나 빌더로 충분한 경우가 많고, 회원 · 예약 · 결제를 직접 돌려야 하면 일반 웹호스팅 쪽이 됩니다. 이것은 일반적인 구분이며 업체마다 기능이 다릅니다.

3정적 호스팅은 어떤 조건을 지켜야 하나요?

정적 호스팅의 예로 GitHub Pages 공식 문서를 보면 한도가 분명합니다. 게시 사이트는 1GB 이하, 대역폭은 월 100GB의 소프트 한도입니다. 또 온라인 비즈니스, 전자상거래 사이트, 상업적 거래를 주로 돕는 사이트를 돌리는 무료 호스팅으로는 허용되지 않고, 비밀번호 · 카드 번호 같은 민감한 거래에도 쓰지 말라고 안내합니다.

SSL은 편합니다. 사용자 지정 도메인을 넣으면 DNS 설정을 검사한 뒤 Let's Encrypt 인증서를 자동으로 받아 붙이고, 'HTTPS 적용'을 켜면 http 접속이 https로 넘어갑니다. 파일이 저장소(리포지토리)에 그대로 남아 있어서 옮기기도 쉽습니다.

4빌더로 만들면 주소와 인증서는 누구 손에 있나요?

빌더의 예로 Google Sites 맞춤 주소 문서를 보면, 사이트는 확인된 도메인에만 연결할 수 있고 다른 도메인 이름에 속한 주소에는 연결할 수 없습니다. 연결하면 도메인 검증 SSL 인증서가 자동으로 붙고, 다른 인증서는 쓸 수 없습니다. 무료 체험 계정으로는 연결이 안 되고, 반영에 최대 24시간이 걸릴 수 있습니다.

같은 문서는 사이트를 만든 도메인에 따라 소유권 이전이 안 될 수 있고, 그때는 새 도메인에서 사본을 만들어야 한다고 적습니다. 빌더는 '어느 계정이 사이트를 가졌나'를 처음부터 사장님 계정으로 맞춰 두십시오.

5일반 웹호스팅이라면 보안 점검은 어디서 받나요?

서버 프로그램을 돌리면 업데이트와 보안이 사장님 몫으로 남습니다. KISA 보호나라의 '내 서버 돌보미'는 중소기업기본법상 중소기업의 웹 · DB 서버를 원격으로 점검하는 서비스로, Windows 111개 · Linux/UNIX 100개 항목을 보고 운영체제 설정 · 공개 취약점 · 침해 흔적을 확인합니다. 신청은 보호나라의 온라인 서비스 신청 메뉴에서 합니다.

같은 누리집의 '중소기업 홈페이지 보안강화'는 웹셸 · 랜섬웨어 같은 해킹 프로그램 확인과 웹 공격 차단(사이버대피소)을 함께 묶어 안내합니다. 비용 · 모집 조건은 신청 전에 보호나라에서 다시 확인하십시오.

6옮기기로 했다면 어떤 순서로 하나요?

  1. 지금 호스팅에서 전체 파일(DB가 있으면 DB까지)을 내려받아 내 컴퓨터와 클라우드 두 곳에 둡니다.
  2. 도메인 등록인이 사장님 명의인지, 등록대행자 계정에 직접 로그인되는지 확인합니다.
  3. 새 호스팅에 파일을 올리고, 임시 주소로 모든 페이지 · 문의 폼이 열리는지 봅니다.
  4. DNS를 새 서버로 바꾸고 SSL 인증서가 붙었는지 https 주소로 확인합니다.
  5. 페이지 주소가 바뀌었다면 301 리디렉션 글대로 옛 주소를 이어 줍니다.
  6. 옛 호스팅 해지는 며칠 지켜본 뒤에 합니다.

옮긴 뒤 검색 노출이 그대로인지는 무료 SEO 점검으로 볼 수 있습니다. 어느 방식이 맞는지 정하기 어렵다면 제작 문의에 지금 홈페이지 주소를 남겨 주십시오. 전국 비대면으로 진행합니다.

자주 묻는 질문

가게 홈페이지를 GitHub Pages에 올려도 되나요?

GitHub Pages 문서는 온라인 비즈니스, 전자상거래, 상업적 거래를 주로 돕는 사이트를 돌리는 무료 호스팅으로 쓰는 것을 허용하지 않는다고 적습니다. 용도가 여기에 해당하는지 약관을 먼저 확인하십시오.

빌더로 만든 홈페이지도 내 도메인을 붙일 수 있나요?

대부분 가능합니다. 예를 들어 Google Sites는 확인된 도메인에 맞춤 주소를 연결할 수 있고 SSL 인증서도 자동으로 붙습니다. 다만 무료 체험 계정은 연결할 수 없습니다.

호스팅을 바꾸면 홈페이지 주소도 바뀌나요?

도메인이 사장님 명의라면 DNS만 새 서버로 바꾸면 되고 주소는 그대로입니다. 페이지별 주소가 바뀔 때만 301 리디렉션으로 옛 주소를 이어 줍니다.

서버 보안 점검은 어디에 신청하나요?

중소기업이라면 KISA 보호나라의 '내 서버 돌보미'를 온라인 서비스 신청 메뉴에서 신청할 수 있습니다. 모집 조건은 신청 시점에 보호나라에서 확인하십시오.
