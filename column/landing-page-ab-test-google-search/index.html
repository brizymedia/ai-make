랜딩페이지 A/B 테스트 — 연말 이벤트 페이지 두 버전, 검색에 해 없이 비교하는 법

2026-11-19 · 큰길브리지 · 읽는 시간 약 6분
랜딩페이지 A/B 테스트A/B 테스트 검색 영향A/B 테스트 canonical302 리디렉션 테스트

랜딩페이지 A/B 테스트는 한 번에 한 가지(제목 · 버튼 · 사진 중 하나)만 바꾼 두 버전을 같은 기간 동시에 보여 주고, 문의 버튼을 누른 비율을 비교하면 됩니다. 검색 순위가 걱정된다면 Google Search Central이 안내하는 네 가지만 지키면 됩니다. Googlebot과 사람에게 다른 페이지를 보여 주지 않기, 변형 주소에 rel="canonical" 달기, 리디렉션은 302(임시)로 하기, 테스트가 끝나면 이긴 버전만 남기고 테스트 장치를 빨리 지우기입니다.

핵심만 먼저
  • 한 번에 한 요소만 바꿉니다. 제목과 사진을 같이 바꾸면 무엇 때문에 결과가 달라졌는지 알 수 없습니다(일반 요령).
  • Googlebot에게만 다른 버전이나 다른 주소 묶음을 보여 주면 클로킹입니다. 서버 설정이든 robots.txt든 방법과 상관없이 하면 안 됩니다(Google 안내).
  • B 버전을 다른 주소로 만들었다면 그 주소에 원래 페이지를 가리키는 rel="canonical"을 답니다. Google은 noindex보다 canonical이 테스트 의도에 더 맞다고 안내합니다.
  • A 주소에서 B 주소로 보내는 방식이면 301(영구)이 아니라 302(임시) 리디렉션을 씁니다. 자바스크립트 리디렉션도 괜찮습니다.
  • 기간은 정해진 일수가 없습니다. 필요한 만큼만 돌리고, 끝나면 이긴 버전으로 고친 뒤 테스트 요소를 최대한 빨리 지웁니다.

1랜딩페이지 A/B 테스트, 사장님 가게에는 왜 필요한가요?

연말 이벤트 페이지는 보통 한 달 남짓 쓰고 내립니다. 짧은 기간에 문의를 한 건이라도 더 받으려면 '어떤 제목이 더 눌리나'를 감으로 정하지 말고 숫자로 확인하는 편이 낫습니다. A/B 테스트는 페이지를 두 버전(A, B)으로 만들어 방문자를 나눠 보여 주고, 어느 쪽이 예약 · 전화 · 문의 버튼을 더 많이 눌렀는지 비교하는 방법입니다.

걱정되는 것은 대개 하나입니다. '페이지를 두 개 만들면 구글이 중복 페이지로 보고 순위를 내리지 않을까?' Google Search Central의 'A/B 테스트가 Google 검색에 미치는 영향 최소화' 문서는 몇 가지 원칙만 지키면 테스트가 검색에 주는 영향을 줄일 수 있다고 안내합니다. 아래 3장에서 그 원칙을 정리했습니다.

3검색에 해가 가지 않게 하려면 무엇을 지켜야 하나요?

302테스트 리디렉션에 쓰는 임시 리디렉션(Google 안내)
301테스트에는 쓰지 않는 영구 리디렉션(Google 안내)

Google Search Central 문서(영문 원문을 우리말로 풀어 옮김)가 안내하는 원칙은 네 가지입니다.

원칙Google 안내 내용사장님 페이지에 적용하면
클로킹 금지Googlebot과 사람에게 서로 다른 URL 묶음을 보여 주지 말 것. 서버 로직이든 robots.txt든 방법과 무관검색 로봇에게만 A를 고정해 보여 주는 설정을 하지 않습니다
rel="canonical"여러 주소로 변형을 만들면 변형 주소에 canonical을 쓸 것. noindex 메타 태그보다 의도에 더 맞음B 주소의 머리말에 원래 A 주소를 가리키는 canonical을 답니다
302 리디렉션원래 주소에서 변형 주소로 보낼 때 301(영구)이 아닌 302(임시) 사용. 자바스크립트 리디렉션도 괜찮음A 주소로 온 손님 일부를 B로 보낼 때 302로 설정합니다
필요한 기간만실험은 필요한 만큼만 하고, 끝나면 원하는 버전으로 사이트를 고친 뒤 테스트 요소를 최대한 빨리 제거이벤트 종료 전에 결론을 내고 B 주소 · 분배 코드를 정리합니다
noindex로 B 버전을 숨기는 방법을 먼저 떠올리기 쉽지만, Google은 이 경우 noindex보다 rel="canonical"이 더 적합하다고 안내합니다. 또 301은 '이 주소가 영구히 옮겨 갔다'는 뜻이라 테스트용으로는 맞지 않습니다.

4테스트는 어떤 순서로 진행하나요?

아래 순서는 일반 요령입니다. 3장의 Google 원칙은 4~5번 단계에서 챙깁니다.

  1. 목표 하나를 정합니다. 예: '남은 날짜 확인' 버튼 클릭 수.
  2. 버튼 클릭을 셀 수 있게 합니다. GA4에서 버튼 클릭을 키 이벤트로 잡아 두면 A와 B를 같은 기준으로 비교할 수 있습니다. 설정 방법은 홈페이지 GA4 키 이벤트 설정 글에 정리해 두었습니다.
  3. B 버전을 만듭니다. 2장 표에서 한 요소만 바꿉니다.
  4. 방문자를 나눕니다. 같은 기간에 A와 B를 번갈아 보여 줍니다. 주소를 나눴다면 B에 rel="canonical"을, 보내는 방식이면 302를 씁니다.
  5. 검색 로봇을 따로 대하지 않습니다. Googlebot도 일반 방문자와 똑같이 나눠지게 둡니다.
  6. 결과를 보고 정리합니다. 이긴 버전으로 원래 페이지를 고치고, B 주소와 분배 코드를 지웁니다.

5얼마나 오래 돌려야 결과를 믿을 수 있나요?

Google 문서에는 '며칠'이라는 기준이 없습니다. 필요한 기간은 전환율과 트래픽에 따라 달라진다고만 안내합니다. 하루 방문자가 많은 페이지는 빨리 차이가 보이고, 방문자가 적은 동네 가게 페이지는 더 오래 봐야 합니다.

  • 일반 요령 — 평일과 주말 손님이 다르므로 최소한 주말을 한 번 이상 포함해 봅니다.
  • 일반 요령 — 클릭 수가 몇 번 차이 날 때는 우연일 수 있습니다. 차이가 계속 같은 방향으로 유지되는지 봅니다.
  • 일반 요령 — 중간에 광고를 새로 켜거나 가격 · 혜택을 바꾸면 비교가 흐려집니다. 테스트 기간에는 다른 조건을 그대로 둡니다.
  • Google 안내 — 결론이 나면 오래 끌지 말고 이긴 버전으로 고친 뒤 테스트 요소를 최대한 빨리 지웁니다.
연말 이벤트처럼 기간이 짧은 페이지라면 이벤트 시작 직후 1~2주 안에 버튼 문구처럼 효과가 바로 보이는 요소 하나만 시험해 보는 편이 현실적입니다(일반 요령).

6직접 하기 어렵다면 어떻게 하나요?

A/B 테스트는 페이지를 두 벌 만들고, 방문자를 나누고, 클릭을 세는 세 가지가 갖춰져야 합니다. 지금 페이지가 검색에 어떻게 잡히는지는 무료 SEO 점검으로 먼저 확인해 볼 수 있습니다.

큰길브리지는 홈페이지 · 랜딩페이지 제작을 전국 비대면으로 진행합니다. 연말 이벤트 페이지를 두 버전으로 만들어 비교해 보고 싶다면 제작 문의에 남겨 주세요.

자주 묻는 질문

A/B 테스트로 페이지가 두 개가 되면 구글 순위가 떨어지나요?

Google Search Central은 클로킹을 하지 않고, 변형 주소에 rel="canonical"을 달고, 리디렉션은 302를 쓰고, 테스트를 필요한 기간만 하면 검색에 주는 영향을 줄일 수 있다고 안내합니다.

B 버전 페이지에 noindex를 달면 안 되나요?

Google은 변형 주소에는 noindex 메타 태그보다 원래 페이지를 가리키는 rel="canonical"이 테스트 의도에 더 맞다고 안내합니다.

A에서 B로 보낼 때 301과 302 중 무엇을 쓰나요?

302(임시) 리디렉션을 씁니다. 301은 영구 이동이라는 뜻이라 테스트에는 맞지 않습니다. Google은 자바스크립트 리디렉션도 괜찮다고 안내합니다.

테스트는 며칠 동안 해야 하나요?

정해진 일수는 없습니다. Google은 필요한 기간이 전환율과 트래픽에 따라 다르다고 안내하며, 끝나면 원하는 버전으로 고치고 테스트 요소를 빨리 지우라고 권합니다.
