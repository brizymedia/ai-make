홈페이지 보안 설정HSTS 설정Strict-Transport-Security홈페이지 HTTPS 강제

홈페이지 보안 설정은 거창한 장비보다 HTTPS 강제 · 업데이트 · 문의폼 스팸 막기 · 백업 네 가지가 먼저입니다. HTTPS 강제는 HTTP 주소로 들어온 손님을 301 리다이렉트로 HTTPS로 보내고, 'Strict-Transport-Security'(HSTS) 헤더로 브라우저가 다음부터 HTTPS로만 접속하게 기억시키는 두 단계로 합니다. 관리자 계정과 플러그인은 최신 보안 패치를 적용하고, 문의폼은 스팸 방지 장치를 달고, 백업은 홈페이지 서버 밖에 따로 둡니다.

핵심만 먼저
  • HTTPS 강제는 두 단계입니다. HTTP→HTTPS 301 리다이렉트와 HSTS 헤더를 함께 둡니다.
  • HSTS 예시는 'Strict-Transport-Security: max-age=31536000; includeSubDomains' 입니다. max-age 31536000초는 1년입니다.
  • HSTS 헤더는 HTTP로 받으면 무시되고 첫 HTTP 방문은 중간자 공격에 취약하므로, 301 리다이렉트를 빼면 안 됩니다(MDN).
  • KISA 보호나라는 홈페이지 운영자에게 최신 보안 패치 적용과 웹셸 업로드 여부 · 주요 로그 점검을 권고합니다.
  • 문의폼 스팸과 백업은 일반 요령입니다. 스팸 방지 장치를 달고, 백업은 서버 밖에 두고 복원까지 한 번 해 봅니다.

작은 가게 홈페이지가 겪는 문제는 대개 비슷합니다. 주소창에 '주의 요함'이 뜨거나, 오래된 플러그인 때문에 이상한 글이 올라가거나, 문의폼에 광고 글이 쏟아지거나, 서버 문제로 화면이 사라지는 일입니다. 아래 네 가지를 순서대로 챙기면 대부분 막거나 되살릴 수 있습니다.

2HTTPS 강제는 어떻게 하나요? HSTS 헤더 읽는 법

HSTS는 HTTP Strict Transport Security의 줄임말로, 서버가 브라우저에 '이 사이트는 HTTPS로만 들어오라'고 알려 주는 응답 헤더입니다. MDN에 실린 문법은 'Strict-Transport-Security: max-age=<expire-time>; includeSubDomains; preload' 입니다.

항목MDN 설명사장님이 볼 점
max-ageHTTPS를 통해서만 사이트에 접근할 수 있음을 브라우저가 기억해야 하는 시간(초)예시 값 31536000 = 1년. 0이면 HSTS 해제
includeSubDomains지정하면 이 규칙이 사이트의 모든 하위 도메인에도 적용shop. · blog. 같은 하위 주소도 전부 HTTPS가 되는지 먼저 확인
preloadmax-age 31536000 이상 + includeSubDomains가 필요, 명세에는 포함되지 않음되돌리기 어려운 선택이라 처음에는 빼는 편이 안전(일반 요령)

MDN 예시는 'Strict-Transport-Security: max-age=31536000; includeSubDomains' 입니다. 이 줄을 호스팅 관리 화면이나 서버 설정에서 응답 헤더로 추가합니다.

MDN은 HTTP로 받은 HSTS 헤더는 무시되고, 첫 HTTP 방문은 중간자 공격에 취약하다고 설명합니다. 그래서 HTTP→HTTPS 301 리다이렉트는 HSTS를 켠 뒤에도 그대로 둬야 합니다. HSTS만 켜고 리다이렉트를 빼면 처음 오는 손님은 보호받지 못합니다.
  1. 보안 인증서(SSL)가 설치돼 https:// 주소가 정상으로 열리는지 확인합니다.
  2. http:// 로 들어오면 같은 페이지의 https:// 로 301 이동하도록 설정합니다.
  3. 일반 요령 — 처음에는 max-age를 짧게 두고 화면 · 문의폼 · 결제가 모두 정상인지 확인합니다.
  4. 문제가 없으면 max-age=31536000 으로 늘리고, 하위 주소까지 HTTPS가 준비됐을 때만 includeSubDomains 를 붙입니다.
  5. 되돌려야 하면 max-age=0 을 보내 HSTS를 해제합니다.

3관리자 계정과 플러그인은 어떻게 관리하나요?

KISA 보호나라는 홈페이지 운영자 대상 PHP 보안 취약점 안내에서 최신 보안 패치(권장 버전 이상) 적용과 웹셸 업로드 여부 및 주요 로그 점검을 권고합니다. 웹셸은 해커가 홈페이지 서버에 몰래 올려 원격으로 조종하는 악성 파일을 말합니다.

  • 보호나라 권고 — 홈페이지 프로그램 · PHP를 권장 버전 이상으로 올리고 최신 보안 패치를 적용합니다.
  • 보호나라 권고 — 업로드 폴더에 낯선 파일(웹셸)이 없는지, 주요 로그에 이상한 접속이 없는지 점검합니다.
  • 일반 요령 — 쓰지 않는 플러그인 · 테마는 꺼 두지 말고 지웁니다. 꺼 둔 것도 파일은 남아 있습니다.
  • 일반 요령 — 관리자 아이디를 admin 같은 흔한 이름으로 두지 않고, 비밀번호는 다른 사이트와 다르게 씁니다.
  • 일반 요령 — 2단계 인증을 지원하면 켜고, 퇴사한 직원 · 끝난 제작사 계정은 바로 지웁니다.
보호나라 누리집 서비스 메뉴에는 '중소기업 홈페이지 보안강화' 항목이 있습니다. 혼자 점검하기 어렵다면 KISA 상담센터(국번 없이 118)에 문의할 수 있습니다.

4문의폼 스팸은 어떻게 줄이나요?

문의폼은 손님이 연락하는 문이지만, 자동 프로그램이 광고 글이나 피싱 링크를 넣는 통로가 되기도 합니다. 아래는 일반 요령입니다.

방법효과주의할 점
스팸 방지 확인 장치(캡차 등)자동 프로그램 입력을 걸러 냄너무 어려우면 진짜 손님도 포기함
숨은 입력칸(허니팟)사람 눈에 안 보이는 칸을 채운 입력을 버림손님 화면에는 아무 변화 없음
링크 · 첨부 제한피싱 링크 · 악성 파일 차단꼭 필요한 첨부만 허용
받는 칸 줄이기개인정보를 덜 모아 유출 피해를 줄임이름 · 연락처 · 문의 내용 정도면 충분
일반 요령 — 문의폼으로 들어온 글 속 링크는 누르지 않습니다. 손님을 가장한 피싱일 수 있습니다.

5백업은 어디에, 얼마나 자주 해야 하나요?

보안 설정을 다 해도 사고는 날 수 있습니다. 그때 되살릴 수 있느냐는 백업에 달려 있습니다. 아래 순서는 일반 요령입니다.

  1. 백업할 것을 정합니다. 홈페이지 파일, 데이터베이스(글 · 문의 내역), 업로드한 사진입니다.
  2. 백업 파일은 홈페이지 서버 밖(내 컴퓨터, 다른 저장소)에 따로 둡니다. 같은 서버에만 두면 서버와 함께 잃습니다.
  3. 글이나 상품을 자주 바꾸는 홈페이지일수록 자주, 업데이트 직전에는 꼭 백업합니다.
  4. 가끔은 백업 파일로 실제 복원을 해 봅니다. 열리지 않는 백업은 없는 것과 같습니다.
  5. 도메인 · 호스팅 · 관리자 계정 정보를 한곳에 정리해 사장님이 직접 보관합니다.

자주 묻는 질문

HSTS만 켜면 301 리다이렉트는 지워도 되나요?

안 됩니다. MDN은 HTTP로 받은 HSTS 헤더는 무시되고 첫 HTTP 방문은 중간자 공격에 취약하므로 HTTP→HTTPS 301 리다이렉트가 여전히 필요하다고 안내합니다.

max-age=31536000은 무슨 뜻인가요?

브라우저가 이 사이트에 HTTPS로만 접속해야 한다고 기억하는 시간이 31536000초, 곧 1년이라는 뜻입니다. 0으로 보내면 HSTS가 해제됩니다.

includeSubDomains는 꼭 넣어야 하나요?

선택 항목입니다. 넣으면 모든 하위 도메인에 같은 규칙이 적용되므로, 하위 주소가 전부 HTTPS로 열리는지 확인한 뒤에 넣습니다.

홈페이지가 해킹된 것 같으면 어디에 물어보나요?

KISA 보호나라 누리집에서 안내를 확인하거나 KISA 상담센터(국번 없이 118)에 문의할 수 있습니다. 보호나라는 웹셸 업로드 여부와 주요 로그 점검을 권고합니다.
