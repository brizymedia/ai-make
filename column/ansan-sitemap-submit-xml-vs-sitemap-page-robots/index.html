안산 사이트맵 제출 — sitemap.xml과 사이트맵 페이지 차이, robots.txt · 제출 상태

2026-10-22 · 큰길브리지 · 읽는 시간 약 7분
안산 사이트맵 제출sitemap.xml사이트맵 페이지robots.txt Sitemap

안산 사이트맵 제출에서 먼저 가릴 것은 '사이트맵'이라는 이름의 두 가지입니다. 손님이 메뉴 대신 보는 사이트맵 페이지(HTML)와 검색로봇에게 주소 목록을 넘기는 sitemap.xml 파일은 하는 일이 다르고, 서치콘솔 · 서치어드바이저에 제출하는 것은 XML 파일 쪽입니다. 파일을 만든 뒤에는 robots.txt에 한 줄을 적고, 제출한 다음 상태 표시를 읽을 줄 알면 됩니다. Google · 네이버 공식 문서에서 확인한 범위로 정리했습니다.

핵심만 먼저
  • 서치콘솔 · 서치어드바이저에 제출하는 것은 sitemap.xml 같은 XML 파일이고, 사람용 사이트맵 페이지는 제출 대상이 아닙니다.
  • Google은 페이지가 약 500개 이하이고 링크가 잘 이어진 작은 사이트라면 사이트맵이 꼭 필요하지 않을 수 있다고 설명합니다.
  • robots.txt의 Sitemap 줄은 https부터 시작하는 전체 주소로 쓰고, 여러 줄을 둘 수 있습니다.
  • Google은 priority · changefreq 값을 무시하고, lastmod는 실제 수정일과 맞을 때만 씁니다.
  • 서치콘솔 상태가 '성공'이어도 '발견된 페이지' 수가 곧 색인 수는 아닙니다.

1사이트맵 페이지와 sitemap.xml, 같은 것인가요?

이름만 같고 읽는 쪽이 다릅니다. Google 검색 센터는 사이트맵을 '사이트에 있는 페이지, 동영상 및 기타 파일과 각 관계에 관한 정보를 제공하는 파일'이라고 정의합니다. 이 파일은 검색로봇이 읽는 XML 문서입니다. 반면 홈페이지 맨 아래 '사이트맵' 메뉴를 누르면 나오는 목차 화면은 사람이 보는 보통 웹페이지입니다.

구분사이트맵 페이지(HTML)sitemap.xml(XML)
읽는 쪽손님Google · 네이버 검색로봇
생김새메뉴 · 페이지 제목이 링크로 나열된 화면<url><loc>주소</loc></url>가 반복되는 글자 파일
어디에 두나푸터 링크 등 사이트 안보통 도메인 바로 아래(/sitemap.xml)
검색엔진에 알리는 법다른 페이지처럼 링크로 연결서치콘솔 · 서치어드바이저 제출, robots.txt Sitemap 줄
꼭 지킬 것링크를 <a href>로 만들 것UTF-8, 절대 주소, 크기 제한

사람용 사이트맵 페이지를 만든다면 링크를 꼭 href가 있는 a 요소로 만듭니다. Google 링크 권장사항은 href 없이 스크립트로만 움직이는 링크에서는 주소를 안정적으로 뽑아낼 수 없다고 적고 있습니다. 메뉴가 깊지 않은 작은 가게 홈페이지라면 사람용 사이트맵 페이지보다 메뉴 이름을 손님 질문으로 짓는 것이 먼저입니다.

2작은 홈페이지에도 sitemap.xml이 필요한가요?

Google은 사이트맵이 필요할 수 있는 경우로 큰 사이트, 외부 링크가 적은 새 사이트, 동영상 · 이미지가 많은 사이트를 듭니다. 반대로 검색결과에 내보낼 페이지가 약 500개 이하이고 홈에서 링크를 따라 모든 중요한 페이지에 닿을 수 있다면 필요하지 않을 수 있다고 설명합니다. 네이버 서치어드바이저는 검색결과에서 내 사이트 노출이 적다면 RSS와 사이트맵 제출을 권하고, 사이트맵에는 사이트의 모든 URL을 담기를 권장합니다.

결국 갓 만든 홈페이지는 바깥에서 들어오는 링크가 거의 없으니 두 검색엔진 모두에 제출해 두는 편이 낫습니다. 두 곳의 기준은 조금씩 다릅니다.

항목Google 검색 센터네이버 서치어드바이저
파일 한 개 한도압축 전 50MB 또는 URL 50,000개10MB 이상 제출 불가, URL 50,000개 이상 불가
담을 주소검색에 내보낼 주소사이트 내 모든 URL 권장
priority · changefreq무시함선택 요소로 안내
lastmod일관되고 실제와 맞을 때만 사용선택 요소(페이지 수정 날짜)
주소 조건정규화된 절대 URL소유확인한 사이트와 같은 도메인
lastmod는 본문 · 구조화 데이터 · 링크가 바뀌었을 때만 고칩니다. Google은 저작권 연도 같은 사소한 변경은 해당하지 않는다고 적습니다. 매일 모든 날짜를 오늘로 바꾸는 자동 설정은 오히려 신뢰를 잃습니다.

3robots.txt의 Sitemap 줄은 어떻게 쓰나요?

제출 화면에 들어가지 않아도 검색로봇이 사이트맵을 찾게 하는 방법이 robots.txt 한 줄입니다. 네이버 robots.txt 안내는 아래처럼 User-agent · Allow 줄 다음에 Sitemap 줄을 적는 예를 보여 줍니다.

User-agent: * / Allow: / / Sitemap: http://www.example.com/sitemap.xml— 네이버 서치어드바이저 — robots.txt 설정하기(예시, 줄바꿈은 / 로 표시)
  • 전체 주소로 — Google 사양 설명은 Sitemap 값이 프로토콜과 호스트를 포함한 정규화된 URL이어야 한다고 적습니다. /sitemap.xml 처럼 쓰지 않습니다.
  • 여러 줄 가능 — 사이트맵 수에 제한 없이 여러 Sitemap 줄을 둘 수 있습니다. 이 사이트(큰길브리지)도 홈페이지 · 칼럼 · 카드용 사이트맵을 세 줄로 따로 적어 둡니다.
  • User-agent와 무관 — Sitemap 줄은 특정 검색로봇 묶음에 속하지 않고, 크롤링이 허용된 모든 로봇이 따를 수 있습니다.
  • 고친 뒤 알리기 — Google은 다음에 robots.txt를 가져갈 때 확인하고, 네이버는 웹마스터도구의 robots.txt 도구에서 수집 요청을 눌러 빠르게 알릴 수 있습니다.

4제출은 어떤 순서로 하나요?

  1. 브라우저 주소창에 https://내도메인/sitemap.xml 을 넣어 파일이 열리는지, 안의 주소가 모두 https 전체 주소인지 확인합니다.
  2. Google Search Console에서 URL 검사로 사이트맵 주소를 라이브 테스트해 페이지 가져오기가 '성공'인지 봅니다.
  3. 사이트맵 보고서의 '새 사이트맵 추가' 칸에 그 주소를 붙여 넣고 제출합니다. 속성 소유자 권한이 없다면 robots.txt Sitemap 줄로 대신 알릴 수 있습니다.
  4. 네이버 서치어드바이저에서는 소유확인한 사이트의 요청 메뉴에서 사이트맵을 제출합니다. 메뉴 위치는 네이버 등록 순서 글에 정리해 두었습니다.
  5. 사이트맵이 여러 개라면 사이트맵 인덱스 파일 하나로 묶어 제출해도 됩니다. Google은 인덱스로 제출하면 사이트맵별 실적을 따로 보기 쉽다고 안내합니다.

5제출한 뒤 '가져올 수 없음'이 뜨면 무엇을 보나요?

서치콘솔 상태공식 설명먼저 볼 곳(일반 요령)
성공오류 없이 로드 · 처리됨발견된 페이지 수와 실제 페이지 수 비교
오류 발생가져왔지만 오류가 하나 이상 있음사이트맵을 눌러 오류 목록 확인, 상대 주소 · 다른 도메인 주소
가져올 수 없음어떤 이유로든 파일을 가져오지 못함파일 주소 오타, 로그인 필요 여부, robots.txt 차단, 서버 응답

'성공'이라도 끝이 아닙니다. Search Console 도움말은 '발견된 페이지'가 사이트맵에서 읽어 낸 URL 수일 뿐 크롤링이나 색인을 보장하지 않는다고 적습니다. 실제 색인 수는 페이지 색인 생성 보고서를 해당 사이트맵으로 걸러서 확인합니다. 색인을 하나씩 확인하는 URL 검사 사용법은 구글 서치콘솔 글에 있습니다.

6안산 공장 · 납품 업체 홈페이지라면 무엇을 더 챙기나요?

안산시 누리집의 '안산시 현황'에 따르면 2026년 1월 1일 기준 안산의 기업체는 12,371개, 종업원은 150,712명이고, 산업단지별로는 반월 국가산업단지가 8,854개로 가장 많습니다. 같은 자료에서 전체 인구 713,708명 가운데 외국인 주민이 101,200명입니다.

  • 제품 · 설비 · 인증서를 페이지 하나에 몰지 말고 품목별 페이지로 나누면, 거래처 담당자가 품목 이름으로 검색했을 때 들어올 문이 늘어납니다. 새 품목 페이지를 올릴 때마다 sitemap.xml에 주소가 추가되는지 확인합니다.
  • 카탈로그를 고친 날에만 해당 페이지의 lastmod를 바꿉니다.
  • 영문 · 다국어 페이지를 따로 두었다면 각 언어 주소도 사이트맵에 넣습니다. 언어 페이지 구조는 영문 홈페이지 글을 참고하세요.

사이트맵이 제대로 제출됐는지 모르겠다면 무료 SEO 점검에 주소를 남겨 주세요. 안산 업체의 홈페이지 점검과 제작은 전국 비대면으로 진행하며, 새로 만들거나 고칠 일이 있으면 제작 문의로 연락 주시면 됩니다.

자주 묻는 질문

홈페이지 푸터의 '사이트맵' 페이지를 서치콘솔에 제출하면 되나요?

아닙니다. 서치콘솔 · 서치어드바이저에는 sitemap.xml 같은 XML 사이트맵 파일 주소를 제출합니다. 사람용 사이트맵 페이지는 다른 페이지처럼 링크로 연결해 두면 됩니다.

robots.txt에 Sitemap 줄을 쓰면 서치콘솔 제출은 안 해도 되나요?

Google은 robots.txt의 Sitemap 줄도 제출 방법 중 하나로 안내합니다. 다만 서치콘솔 사이트맵 보고서에 제출하면 Googlebot이 언제 가져갔는지, 처리 오류가 있었는지 볼 수 있어 함께 하는 편이 좋습니다.

사이트맵 상태가 '성공'인데 검색에 안 나옵니다.

'발견된 페이지'는 사이트맵에서 읽어 낸 주소 수일 뿐 색인을 보장하지 않습니다. 페이지 색인 생성 보고서를 해당 사이트맵으로 걸러 실제 색인 여부를 확인합니다.

priority 값을 높이면 먼저 수집되나요?

Google은 priority와 changefreq 값을 무시한다고 밝힙니다. 네이버는 선택 요소로 안내합니다. 주소(loc)를 정확히 넣는 것이 먼저입니다.
