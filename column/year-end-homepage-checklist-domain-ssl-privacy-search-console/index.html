연말 홈페이지 점검은 다섯 줄짜리 표 한 장이면 됩니다. 도메인이 언제 끝나는지, 주소창 자물쇠(HTTPS 인증서)가 자동으로 갱신되는지, 처리방침이 올해 바뀐 작성지침과 맞는지, 바닥글 사업자 정보가 지금 사실과 같은지, 검색엔진이 깨진 주소를 얼마나 찾았는지입니다. 항목마다 자세한 방법은 이미 쓴 글로 연결하고, 이 글은 '12월에 무엇을 어떤 순서로 열어 볼지'만 다룹니다.

핵심만 먼저
  • 연말 점검 다섯 줄: 도메인 사용종료일, HTTPS 인증서 자동 갱신, 개인정보 처리방침, 사업자 정보 표시, Search Console 페이지 색인 생성 보고서.
  • 공개 웹 인증서의 최대 유효기간은 2026년 3월부터 줄기 시작해 2029년 3월에는 47일이 됩니다(CA/브라우저 포럼 SC081v3). 손으로 갱신하던 곳은 자동 갱신부터 확인합니다.
  • 개인정보보호위원회는 2026년 4월 24일 처리방침 작성지침을 고쳐 변경 안내 방식과 수탁자 기재 방법을 바꿨습니다.

홈페이지는 한 번 만들면 그대로 있을 것 같지만, 날짜가 정해진 것이 여럿 붙어 있습니다. 도메인은 사용종료일이 있고, 인증서는 만료일이 있고, 처리방침과 사업자 정보는 가게 사정이 바뀌면 낡습니다. 검색엔진은 그사이 사라진 페이지를 계속 찾아옵니다.

연말은 손님이 덜 찾는 기간이 있는 업종이 많아 손보기 좋고, 새해 공지 · 영업시간을 바꾸기 전에 바닥부터 정리해 둘 수 있습니다. 아래 표를 위에서부터 한 줄씩 지워 나가면 됩니다.

3인증서 유효기간이 짧아지면 무엇을 확인하나요?

브라우저 회사와 인증기관이 모인 CA/브라우저 포럼은 2025년 4월 투표(SC081v3)로 공개 TLS 인증서의 최대 유효기간을 398일에서 47일로 줄이기로 했고, 감축은 2026년 3월에 시작해 2029년 3월에 끝납니다. 무료 인증서를 많이 쓰는 Let's Encrypt는 지금 90일 인증서를 기본으로 내고, 2028년 2월까지 최대 45일로 줄일 계획이라고 공식 문서에 적었습니다. 같은 문서는 수명이 짧아질수록 갱신 자동화가 꼭 필요하다고 강조합니다.

  • 호스팅 · 빌더가 알아서 갱신하는 경우 — 관리 화면에 자동 갱신이 켜져 있는지, 알림 메일이 사장님 주소로 오는지만 봅니다.
  • 해마다 인증서를 사서 손으로 넣던 경우 — 앞으로 넣는 횟수가 늘어납니다. 자동 갱신이 되는 방식으로 바꿀 수 있는지 호스팅 업체나 제작 업체에 묻습니다(일반 요령).
  • 만료일 직접 확인 — 주소창 자물쇠를 눌러 인증서 정보를 열면 유효기간이 보입니다. 남은 기간이 짧은데 갱신 기록이 없으면 그날 바로 연락합니다.

4Search Console 보고서에서 연말에 볼 숫자는?

Google 고객센터의 페이지 색인 생성 보고서 안내는 이 보고서가 Google이 찾은 주소의 색인 상태와 색인되지 않은 이유를 보여 준다고 설명합니다. 한 해 동안 메뉴를 바꾸고 글을 지웠다면 아래 세 가지 이유가 쌓여 있기 쉽습니다.

  • 찾을 수 없음(404) — 대체할 페이지 없이 지운 페이지라면 404 자체가 반드시 문제는 아니라고 안내합니다. 옮긴 페이지라면 새 주소로 301 리디렉션을 겁니다.
  • Soft 404 — 화면에는 '없는 페이지'라고 보이는데 실제 응답은 404가 아닌 경우입니다. 정말 없는 페이지면 404를 돌려주게 고칩니다.
  • 리디렉션이 포함된 페이지 — 옛 주소가 새 주소로 넘어가는 중이라는 뜻이라 대개 정상입니다. 리뉴얼로 주소가 바뀐 경우의 짝짓기는 강릉 리뉴얼 글에 있습니다.
  1. 보고서에서 이유별 개수를 적고, 지난해 적어 둔 숫자와 비교합니다.
  2. 404 목록을 열어 '옮긴 페이지'와 '없앤 페이지'를 나눕니다.
  3. 옮긴 페이지는 리디렉션, 홈페이지 안에서 그 주소로 걸린 링크는 새 주소로 고칩니다.
  4. 같은 문제를 전부 고친 뒤 세부정보 화면에서 '수정 결과 확인'을 한 번만 누릅니다. 확인이 끝날 때까지 다시 누르지 않습니다.
  5. 보통 최대 2주가 걸리므로 12월 첫 주에 시작하면 해가 바뀌기 전에 결과를 볼 수 있습니다.

5처리방침과 사업자 정보는 올해 무엇이 달라졌나요?

개인정보보호위원회는 2026년 4월 24일 처리방침 작성지침을 고쳐 공개했습니다. 작은 가게가 연말에 대조할 대목은 세 가지입니다.

  • 변경 안내 — 손님 권리에 중대한 영향을 주는 변경은 고치기 전이나 고친 즉시 알리고, 수탁자 목록처럼 영향이 낮은 변경은 일정 기간(예: 4주)씩 모아 안내할 수 있습니다.
  • 수탁자 유형 기재 — 맡기는 곳이 많거나 자주 바뀌면 유형으로 적을 수 있지만, 실제 업체를 확인할 경로를 함께 둡니다.
  • 생성형 AI 부록 — 상담 챗봇처럼 AI 기능을 붙였다면 입력 · 출력 정보와 학습 활용 여부를 적는 기준이 새로 생겼습니다.

사업자 정보는 법이 바뀐 것이 아니라 가게가 바뀌어서 틀리는 경우가 많습니다. 이사, 대표 번호 변경, 법인 전환이 있었다면 바닥글을 먼저 고칩니다. 스토어를 함께 운영한다면 두 곳의 표기를 맞추는 법을 오늘 쓴 스마트스토어 글에 정리했습니다.

6내년 점검 날짜는 어떻게 잡나요?

  1. 도메인 사용종료일과 인증서 만료일 가운데 빠른 날짜에 한 달 전 · 일주일 전 알림을 겁니다.
  2. 처리방침은 외부 서비스를 바꾸는 날마다 열고, 그 밖에는 분기에 한 번 봅니다.
  3. Search Console은 매달 첫 주에 이유별 개수만 적습니다.
  4. 12월 첫 주를 '연말 홈페이지 점검' 주로 정해 두고 2장 표를 처음부터 다시 돌립니다.

혼자 보기 어려운 줄이 있다면 무료 SEO 점검으로 검색 노출 상태부터 받아 보셔도 됩니다. 고칠 곳이 많아 새로 만드는 편이 낫다면 제작 문의에 지금 주소를 남겨 주십시오. 큰길브리지는 전국 비대면으로 진행합니다.

자주 묻는 질문

연말 홈페이지 점검에서 가장 먼저 볼 것은 무엇인가요?

도메인 사용종료일과 HTTPS 인증서 만료일입니다. 둘 중 하나라도 지나면 손님이 홈페이지를 아예 못 열거나 경고 화면을 보게 되므로, 내용 점검보다 먼저 확인합니다.

인증서 유효기간이 짧아지면 사장님이 할 일이 늘어나나요?

자동 갱신이 되는 호스팅이라면 거의 늘지 않습니다. 해마다 인증서를 사서 손으로 넣던 곳은 넣는 횟수가 늘어나므로 자동 갱신 방식으로 바꿀 수 있는지 먼저 확인하는 편이 좋습니다.

Search Console에 404가 많으면 검색에서 불리한가요?

Google 고객센터는 대체할 페이지 없이 지운 페이지의 404는 반드시 문제가 되지 않는다고 안내합니다. 옮긴 페이지라면 새 주소로 301 리디렉션을 걸고, 홈페이지 안의 링크를 고치면 됩니다.

처리방침은 해마다 새로 써야 하나요?

해마다 새로 쓸 의무가 정해져 있지는 않습니다. 외부 서비스, 폼 항목, 보관 기간처럼 내용이 바뀌었을 때 고치고, 바뀐 내용과 시행일을 알리면 됩니다. 연말에는 실제와 문서가 같은지 대조합니다.
