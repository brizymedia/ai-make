탐색경로 구조화 데이터 — '홈 > 메뉴 > 겨울 메뉴' 경로를 검색에 알리는 법

2026-11-24 · 큰길브리지 · 읽는 시간 약 8분
탐색경로 구조화 데이터BreadcrumbList브레드크럼 구조화 데이터홈페이지 메뉴 경로

탐색경로 구조화 데이터는 화면에 먼저 '홈 > 메뉴 > 겨울 메뉴' 같은 경로 줄을 만들고, 그 줄과 똑같은 내용을 BreadcrumbList로 적어 주는 순서로 넣습니다. Google Search Central의 '탐색경로(BreadcrumbList) 구조화 데이터' 안내 요지는 BreadcrumbList에 ListItem이 최소 2개 있어야 하고, 각 ListItem에는 item · name · position을 적는다는 것입니다. 메뉴 · 시공 사례 · 상품이 여러 단계로 나뉜 가게 홈페이지를 기준으로 정리했습니다.

핵심만 먼저
  • 탐색경로는 '홈 > 메뉴 > 겨울 메뉴'처럼 지금 보는 페이지가 사이트 안 어디에 있는지 보여 주는 줄입니다. 화면에 먼저 만들고 구조화 데이터는 그다음에 넣습니다(일반 요령).
  • BreadcrumbList는 ListItem을 최소 2개 담아야 하고, 필수 속성은 itemListElement입니다(Google 안내 요지).
  • 각 ListItem의 필수 속성은 item(주소) · name(이름) · position(순서)이고, position 1이 경로의 시작입니다(Google 안내 요지).
  • 마지막 항목은 item을 빼도 되며 그때 Google은 그 페이지 주소를 씁니다. 홈 같은 최상위 항목도 꼭 넣지 않아도 됩니다(Google 안내 요지).
  • 넣은 뒤 Google이 찾아서 크롤링하기까지 며칠 걸릴 수 있으니 바로 바뀌지 않아도 기다립니다(Google 안내 요지).

1탐색경로 구조화 데이터는 무엇이고 어떤 홈페이지에 필요한가요?

2개BreadcrumbList에 들어가야 하는 최소 ListItem 수(Google 안내)
position 1탐색경로의 시작 항목 번호(Google 안내)

탐색경로(브레드크럼)는 페이지 위쪽에 작게 보이는 '홈 > 메뉴 > 겨울 메뉴' 같은 줄입니다. 손님은 이 줄을 보고 지금 어디에 있는지 알고, 한 단계 위로 쉽게 돌아갑니다. 탐색경로 구조화 데이터는 이 줄을 검색엔진이 알아듣는 정해진 틀(BreadcrumbList)로 한 번 더 적어 주는 것입니다. Google Search Central 안내(영문 원문을 우리말로 풀어 옮긴 요지)는 이 정보로 페이지가 사이트 안 어디에 있는지 파악하는 데 도움을 받는다고 설명합니다.

필요한 곳은 단계가 두 번 이상 나뉘는 홈페이지입니다. 식당의 '메뉴 > 겨울 메뉴 > 굴국밥', 인테리어 업체의 '시공 사례 > 욕실 > 32평 아파트 욕실', 쇼핑몰의 '상품 > 선물세트 > 한우 세트'처럼요. 첫 화면 한 장과 문의 페이지뿐인 홈페이지라면 급하게 넣을 필요는 없습니다(일반 요령).

검색 결과 맨 위에 보이는 사이트 이름은 탐색경로와 다른 WebSite 구조화 데이터로 알립니다. 그 내용은 검색 사이트 이름 — WebSite 구조화 데이터 글에 정리했습니다.

2왜 화면의 탐색경로부터 만들어야 하나요?

구조화 데이터는 화면 내용을 다시 적어 주는 것이지, 화면에 없는 내용을 새로 지어내는 곳이 아닙니다(일반 요령). 그래서 순서는 늘 화면 먼저, 데이터 나중입니다. 화면에 경로 줄이 없는데 데이터만 넣으면 손님에게는 도움이 안 되고, 나중에 메뉴 구성이 바뀔 때 화면과 데이터가 어긋나기 쉽습니다.

  1. 홈페이지 메뉴를 종이에 그려 봅니다. 홈 아래에 메뉴 · 시공 사례 · 상품 · 오시는 길이 있고, 그 아래 어떤 묶음이 있는지 2~3단계로 적습니다.
  2. 페이지마다 경로 한 줄을 정합니다. 굴국밥 페이지라면 '홈 > 메뉴 > 겨울 메뉴 > 굴국밥'처럼 손님이 실제로 눌러 들어오는 길을 적습니다.
  3. 화면 위쪽에 그 줄을 보이게 넣습니다. 앞 단계 이름은 눌러서 갈 수 있게 링크로, 지금 보는 페이지 이름은 글자로만 둡니다(일반 요령).
  4. 그 줄과 똑같이 BreadcrumbList를 적습니다. 이름 · 순서 · 주소가 화면과 한 글자도 다르지 않게 맞춥니다.
한 페이지가 두 묶음에 걸치는 경우(예: 굴국밥이 '겨울 메뉴'와 '포장 메뉴'에 모두 있음)에는 손님이 가장 많이 들어오는 길 하나를 기본으로 정해 두는 편이 관리하기 쉽습니다(일반 요령).

3꼭 넣어야 하는 속성은 무엇인가요?

Google 안내 요지를 정리하면, 바깥 틀인 BreadcrumbList에는 itemListElement가 필수이고, 그 안에 경로 한 칸씩을 ListItem으로 최소 2개 담습니다. 각 ListItem에는 아래 세 가지를 적습니다.

속성뜻주의할 점
itemListElement (BreadcrumbList 필수)경로 칸들을 담는 목록ListItem을 최소 2개 담습니다
position (ListItem 필수)경로에서 몇 번째 칸인지1이 경로의 시작입니다
name (ListItem 필수)그 칸의 이름화면에 보이는 이름과 똑같이 적습니다(일반 요령)
item (ListItem 필수)그 칸의 주소(URL)마지막 칸은 빼도 되며, 그때 Google은 그 페이지 주소를 씁니다

또 하나 알아 둘 점은 홈 같은 최상위 칸을 반드시 넣지 않아도 된다는 것입니다(Google 안내 요지). 다만 화면 경로 줄에 '홈'이 보인다면 데이터에도 넣어 두는 편이 화면과 맞추기 쉽습니다(일반 요령).

4'홈 > 메뉴 > 겨울 메뉴'는 실제로 어떻게 적나요?

겨울 메뉴 묶음 페이지를 예로 들면, 화면 줄은 '홈 > 메뉴 > 겨울 메뉴'이고 데이터는 아래 표처럼 세 칸이 됩니다. 주소는 예시이니 우리 홈페이지 주소로 바꿔 적습니다.

위치(position)이름(name)주소(item)
1홈https://example.com/
2메뉴https://example.com/menu/
3겨울 메뉴생략 가능(마지막 칸 — 지금 보는 페이지 주소를 씀)

홈페이지 코드에 넣는 모양은 대략 "@type": "BreadcrumbList", "itemListElement": [ { "@type": "ListItem", "position": 1, "name": "홈", "item": "https://example.com/" }, { "@type": "ListItem", "position": 2, "name": "메뉴", "item": "https://example.com/menu/" }, { "@type": "ListItem", "position": 3, "name": "겨울 메뉴" } ] 처럼 됩니다. 시공 사례라면 '홈 > 시공 사례 > 욕실', 쇼핑몰이라면 '홈 > 상품 > 선물세트'로 이름과 주소만 바꾸면 같은 틀을 씁니다.

일반 요령 — 홈페이지 제작 도구(빌더)에 따라 탐색경로 줄과 데이터를 함께 넣어 주는 설정이 있습니다. 직접 코드를 쓰기 전에 설정 메뉴에 '탐색경로' 또는 'Breadcrumb' 항목이 있는지 먼저 찾아보세요.

5자주 하는 실수는 무엇인가요?

  • 칸이 하나뿐 — '겨울 메뉴' 한 칸만 적으면 경로가 아닙니다. ListItem은 최소 2개가 필요합니다(Google 안내 요지).
  • 순서 번호가 뒤바뀜 — position은 시작 칸이 1이고 안쪽으로 갈수록 커집니다. 2부터 시작하거나 번호가 건너뛰지 않게 봅니다(일반 요령).
  • 화면과 이름이 다름 — 화면에는 '겨울 메뉴', 데이터에는 '동절기 신메뉴'처럼 적으면 헷갈립니다. 화면 글자를 그대로 씁니다(일반 요령).
  • 메뉴 개편 후 그대로 둠 — 묶음 이름이나 주소를 바꾸면 화면 줄과 데이터를 같이 고칩니다. 지운 페이지 주소가 경로에 남아 있지 않은지도 봅니다(일반 요령).
  • 가게 정보와 섞음 — 가게 주소 · 영업시간은 탐색경로가 아니라 LocalBusiness로 따로 알립니다. 가게 주소 · 영업시간 구조화 데이터 글을 참고하세요.

6넣은 뒤에는 무엇을 확인하고 얼마나 기다리나요?

  1. 리치 결과 테스트에 페이지 주소를 넣습니다. 탐색경로 항목이 잡히는지, 오류 · 경고가 없는지 봅니다(일반 요령).
  2. 단계가 다른 페이지를 골고루 봅니다. 묶음 페이지(겨울 메뉴)와 상세 페이지(굴국밥)를 하나씩 검사하면 빠진 곳을 찾기 쉽습니다(일반 요령).
  3. 며칠 기다립니다. Google 안내 요지는 게시 후 Google이 페이지를 찾고 크롤링하는 데 며칠 걸릴 수 있다는 것입니다.
  4. Search Console 보고서를 가끔 확인합니다. 구조화 데이터 관련 오류가 새로 생기지 않았는지 봅니다(일반 요령).

자주 묻는 질문

탐색경로 구조화 데이터에 꼭 넣어야 하는 속성은 무엇인가요?

Google 안내에 따르면 BreadcrumbList에는 itemListElement가 필수이고, 그 안의 ListItem마다 item(주소) · name(이름) · position(순서)을 적습니다. ListItem은 최소 2개가 있어야 합니다.

마지막 칸에도 주소(item)를 꼭 적어야 하나요?

아닙니다. Google 안내에 따르면 탐색경로의 마지막 항목이면 item을 생략할 수 있고, 그때 Google은 그 페이지의 주소를 사용합니다.

'홈'은 꼭 첫 칸으로 넣어야 하나요?

Google 안내에 따르면 홈 같은 최상위 경로의 ListItem은 반드시 넣지 않아도 됩니다. 다만 화면 경로 줄에 '홈'이 보인다면 데이터에도 넣어 화면과 맞추는 편이 관리하기 쉽습니다.

넣었는데 검색 결과가 바로 바뀌지 않아요.

Google 안내에 따르면 게시 후 Google이 페이지를 찾고 크롤링하는 데 며칠 걸릴 수 있습니다. 리치 결과 테스트로 오류가 없는지 확인한 뒤 기다려 보세요.

화면에 탐색경로가 없어도 데이터만 넣으면 되나요?

일반 요령으로는 화면의 경로 줄을 먼저 만들고 같은 내용을 데이터로 적는 편이 좋습니다. 손님도 위치를 알 수 있고, 메뉴를 고칠 때 화면과 데이터가 어긋나지 않습니다.
